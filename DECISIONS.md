# DECISIONS

Decision log. Every judgment call made without human input is recorded here. All data is synthetic.

| # | Phase | Decision | Why |
|---|-------|----------|-----|
| D1 | 0 | Venv scripts are invoked as `python -m ...` (never via `.venv/bin/pytest` shebangs). | The workspace path contains spaces, which breaks shebang lines. `python -m` works everywhere. |
| D2 | 0 | `config.get_paths()` honours a `BGOS_ROOT` env var. | Lets tests and the README-quickstart test run the whole pipeline in a temp dir without touching the repo's `data/`. |
| D3 | 0 | Makefile `clean` means "run the data-cleaning stage" (per the brief's target list); `reset` deletes generated files. | Brief lists `data, clean, score...` as pipeline steps. |
| D4 | 1 | Funnel is strictly nested: an agency counts at stage k only if it passed stages 1..k-1. Activity from agencies that skip stages (e.g. a submission from a non-ICP agency) is reported as "out-of-funnel". | Makes monotonic non-increase true by construction and keeps the numbers auditable. |
| D5 | 1 | "Underwriting-ready" = 4 required checklist fields (loss runs, prior carrier, risk description, property/exposure details). COIs and financials are recommended, not required for the funnel, but are weighted in the AI submission-quality score. | Underwriters can quote without COIs/financials on many specialty risks; a funnel that demanded all six would understate activation. |
| D6 | 1 | Funnel "Repeat Submission" = another complete submission within 90 days AFTER the first bind (bind-anchored). Activation retention cohorts (Phase 5) are anchored on FIRST SUBMISSION at 30/60/90 days. | The funnel is strictly ordered (Repeat follows Bound), so the stage must be bind-anchored to stay monotone. A repeat after a bind is the strongest signal the relationship works. First-submission anchoring in cohorts gives much larger n and measures the habit earlier. Both are documented and used for different questions. |
| D7 | 1 | ICP = commercial lines AND (E&S appetite high/medium OR target specialty weight >= 0.70) AND >= 3 producers. Qualification is dated at first touch. | Matches the brief's "E&S/specialty/hard-to-place exposure + minimum producer/deal-flow". Thresholds are in config. |
| D8 | 4 | Tier precedence: Reactivation first, then Tier 1, then Tier 2, else Tier 3. | A dormant agency with past submissions is a different motion (win-back) regardless of fit. |
| D9 | 1 | The database enforces timestamp ordering via CHECK constraints; raw CSVs (which may be dirty) live outside the DB and are cleaned before loading. | Dirty data cannot enter the SQLite layer. |
| D10 | 2 | (Amended by D41: sizing is now for the 20% ship threshold, N = 3,000.) Synthetic funnel is deliberately generous (~35% of raw leads reach a first complete submission; control-arm A baseline ~30%). | With only ~1,500 agencies, a +30% relative lift on a ~5-10% baseline needs thousands per arm; Experiment A could not be adequately powered. I tuned the simulator so A is powered while B (+15%) and C (null) are underpowered on purpose. Real baselines will be lower, and the framework's sample-size calculator will then demand much larger n. Listed under known limits. |
| D11 | 2 | Experiment A population = every agency (all are enrolled in an outreach sequence); arm = ICP-targeted v2 vs Standard v1; outcome = first complete submission within 60 days of first touch. B population = engaged ICP agencies at engagement; outcome = complete submission within 14 days. C population = agencies with a complete submission and none in the 60 days before T0 (2026-07-31); control = no-outreach holdout; outcome = complete submission within 45 days. | Anchors are pre-treatment, so arm assignment cannot depend on the outcome. Only matured units (full follow-up window before the as-of date) are analysed. |
| D12 | 2 | Duplicates keep the same state; injected missing-state and missing-size values never land on a row that is part of a duplicate pair. | Fuzzy dedupe blocks on state; compounding defects would make recall untestable. The cleaner documents that a duplicate with a missing state cannot be merged automatically. |
| D13 | 2 | Inbound web leads' first touch is an `inbound_form` touch that is NOT an engagement event; engagement requires a subsequent open/click/reply/meeting. | Otherwise every inbound lead would be "engaged" by construction. |
| D14 | 2 | Impossible-value injections avoid the first 5 days of the window so injected timestamps stay inside the window. | Keeps the "dates inside window" test meaningful for non-defective values too. |
| D15 | 3 | Dedupe: block on state, difflib ratio >= 0.85 on normalized name cores, union-find, earliest record wins, children remapped; unknown-state agencies are never auto-merged. Validated on a labeled set (manifest duplicates + hard negatives: same name in different states, near-names in one state). | Precision over recall: a false merge corrupts a funnel; a missed duplicate only inflates top-of-funnel slightly. |
| D16 | 3 | Missing size is imputed (specialty median) and flagged; missing state becomes 'UNK' and flagged (geography score 0). Out-of-range bind rate: value nullified and logged. Negative turnaround with sane timestamps: repaired. Quote-before-submission and bound-before-quote: row quarantined (excluded). | Each defect gets one documented action; nothing is silently altered (the quarantine file lists every touched record). |
| D17 | 3 | Quarantined/removed rows slightly change downstream counts (<=9 submissions). Accounting test: raw rows - quarantined rows = clean rows; handled counts equal injected counts exactly for every defect type. | Reconciliation is exact, so no tolerance was needed (recall was 75/75 on the labeled duplicates). |
| D18 | 4 | Tier precedence: Reactivation > Tier 1 > Tier 2 > Tier 3. Reactivation = >=1 complete submission and last one >= 60 days before the as-of date (boundary: exactly 60 days counts). Tier 1 = ICP AND specialty fit >= .70 AND E&S activity >= .50 AND engagement >= .40. Tier 2 = ICP AND score >= .45. Tier 3 = rest (non-ICP is always Tier 3). Actions: Reactivation->reactivation; Tier 3->monitor; Tier 1/2 by stage: pre-engaged->outbound, engaged->onboarding, submitted+->expansion. A fifth action category "monitor" was added for Tier 3 because the brief's four categories have no sensible action for accounts we deliberately do not work. | Dormant accounts with history are a win-back motion regardless of fit. |
| D19 | 4 | Test fix (test was wrong, not the code): the hand-computed commercial_volume check used 49 producers, but the documented formula is ln(1+p)/ln(1+50), which equals 1 only at 50. Changed the fixture to 50. | Formula in code and docstring unchanged. |
| D20 | 4 | Engagement counts opens, clicks, replies, meetings and complete submissions with a 45-day half-life; emails/LinkedIn requests sent are never engagement. | Brief rule 8: no vanity metrics. |
| D21 | 5 | North star = qualified submissions per week: complete submissions from ICP agencies that are NEW (first complete submission) or ACTIVE (previous complete submission < 60 days earlier). Submissions after >= 60 days of silence are counted separately as "reactivated". Inputs: new ICP agencies, new engaged agencies, new activations. Diagnostics: completeness, quote and bind rates (only for weeks old enough to have outcomes). | Keeps the headline tied to healthy, repeating supply rather than one-off resurrections, and avoids send/touch volume. |
| D22 | 5 | Pipeline projection: open pipeline = agencies whose highest stage is ICP/engaged/first-submission/quoted with activity in the last 90 days; each converts at its segment's observed P(bound given stage reached) (overall rate when segment n < 20); revenue = observed average first-bind commission; repeat revenue excluded. Rates include still-open agencies in the denominator, so they are conservative. | Simple, auditable, and clearly assumption-driven; any founder can challenge each input. |
| D23 | 5 | Time-to-quote uses the stored quote_turnaround_hours (cleaned) with an exact SQL median (middle one/two ranks); both "all submissions" and "each agency's first complete submission" scopes are reported. | Brief asks for first-submission-to-quote; the all-submission view has far larger n. |
| D24 | 5 | Cohort retention uses only MATURE agencies (full 30/60/90-day window observed before the as-of date) in each denominator. Activation uses the same rule at 14 days. | Otherwise recent cohorts would look artificially bad (right-censoring). |
| D25 | 6 | Experiment arms are assigned by stratified (blocked) 50/50 randomization (strata = lead source x ICP flag x fit tercile). | With simple randomization the first run gave A lift estimates from +12% to +47% across seeds (covariate imbalance on fit), and seed 42 showed a spurious B lift of -11% against a planted +15%. Blocking is standard practice, removes that avoidable variance, and is not a change to any assertion. Over 8 seeds (42,1-7) A ships in 5/8 runs at a planted +30% (honest power at n~600/arm), B is positive in 8/8, C is never SHIP. |
| D26 | 6 | Required sample size is recomputed from the OBSERVED control rate and the pre-registered relative MDE; "sample size reached" = min(arm n) >= that requirement. Achieved power is computed at the observed effect (post-hoc power, reported for transparency only, never used in a decision). | Planning baselines are unknown in the real world; observed-baseline power analysis is the honest check. |
| D27 | 6 | Decision rule is generic except Experiment A, which follows the brief literally: SHIP iff lift >= 20% AND p < alpha AND n reached, otherwise ITERATE the ICP definition. For B/C: significant-but-small or powered-null => ITERATE; underpowered and not significant => INCONCLUSIVE; SRM flag => INCONCLUSIVE. | Do not iterate on noise. |
| D28 | 6 | B and C are deliberately underpowered in the simulation (B needs ~2,000/arm for +15%, C has ~75/arm). On seed 42 B shows +20% (p=0.02) but cannot be shipped because the required sample is not reached; C is INCONCLUSIVE. | Demonstrates that the framework refuses to ship underpowered wins. |
| D29 | 7 | Provider interface has three LLM-able methods (profile extraction, free-text checklist parsing, first-line writing). Scoring and next-best-action are rules only, never LLM. `get_provider()` returns the Anthropic provider only if ANTHROPIC_API_KEY AND BGOS_LLM_MODEL are both set and the SDK imports; otherwise the mock. The `anthropic` package is intentionally NOT in requirements.txt. | Keeps the default path offline and deterministic; model name is never hard-coded (tested). |
| D30 | 7 | Submission-quality weights: loss runs .25, property details .20, risk description .20, financials .15, prior carrier .10, COIs .10. A submission is "underwriting-ready" iff the four funnel-required items are present, which ties the AI scorer to the funnel definition (tested). | Single definition of completeness across layers. |
| D31 | 7 | Mock text parsing understands simple negation ("loss runs not yet available", "no financials"). An empty/unclear submission scores 0 rather than guessing. | A scorer that silently credits missing documents is worse than none. |
| D32 | 7 | Test hardening: tests monkeypatch `socket` to raise, so any accidental network use fails the suite; a repo-wide grep test bans send-style code (smtplib, requests.post, def send*, ...). | Proves the "no outbound contact" rule rather than asserting it. |
| D33 | 8 | Dashboard reads only data/marts CSVs (written by the SQL metrics layer); takeaway sentences live in `bgos/insights.py` and are computed from those tables; a test fails if currency/thousands literals appear in the app source. Light theme is forced via `.streamlit/config.toml` so charts stay legible regardless of the viewer's OS theme. | No hard-coded numbers; consistent rendering on Streamlit Community Cloud. |
| D34 | 8 | Experiment view shows the planted truth as a red line next to the estimate and CI, and always carries a SIMULATED banner. | Makes it visible that the pipeline recovers a known effect (method validation), and prevents anyone mistaking it for a real result. |
| D35 | 9 | Docs are generated by `make docs` (`src/bgos/docs.py`): DATA_DICTIONARY from schema metadata; STRATEGY_MEMO and LOOM_SCRIPT from the generated marts. A test regenerates them from a fresh seeded run and requires byte equality with the committed files, and a second test requires every number in the memo to be traceable to the facts dict or a short allow-list of structural numbers (30, 60, 90...). | The memo cannot drift from the outputs, and a hand-typed number fails the suite. |
| D36 | 9 | `data/`, `outputs/` are git-ignored; the dashboard bootstraps the seeded pipeline on first load if `data/marts` is missing. | Keeps the repo small and lets Streamlit Community Cloud work without committing generated data. |
| D37 | 9 | The README quickstart test runs `make all` in a temp BGOS_ROOT (skipping `setup`, `dashboard`, `test` to avoid recursion/blocking) and a second test asserts `make all` outputs are byte-identical across runs. | The quickstart is verified, not assumed. |
| D38 | 4 | Scoring is leak-free. (a) Engagement counts opens, clicks, replies and meetings only; complete submissions were removed (they were worth 3 points, so a first submission alone could make an agency Tier 1, and the tier check then "validated" against the same outcome). (b) New tier "Active" (a complete submission in the last 60 days) sits between Reactivation and Tier 1, so Tiers 1-3 contain prospects only. (c) Scores are point-in-time: nothing after the as-of date can influence them. (d) The tier check scores prospects 90 days before the as-of date and counts first submissions in the following 90 days (`tier_holdout.csv`). (e) With submissions gone from engagement, the Tier 1 engagement threshold was set to 0.20 by reasoning (any recent reply or click-plus-open) BEFORE looking at holdout results; the 0.40 threshold had been calibrated while the leak was present. (f) Tier 2 now gets a real "nurture" action. This adds a fifth tier to the brief's four; it is the minimal change that stops existing customers from appearing as prospects. | Audit finding B-17: 77 of 83 Tier 1 accounts had already submitted. |
| D39 | 5 | Funnel/source/owner/pipeline rates are COHORT-MATURE. Each step is measured only on agencies that reached the previous stage at least N days ago (14 / 60 / 60 / 180 / 90 days for engaged / first submission / quoted / bound / repeat, from the observed lag distribution; a test checks each window covers at least 90% of observed lags among old cohorts). Cumulative = product of step rates; suppressed if any step's mature base < 20. Observed (immature) rates are kept and labelled as understating. Pipeline projection counts only PENDING agencies (reached their stage within the next step's window) and uses remaining mature step rates. | Audit finding B-18: recent leads had not had time to convert, so lead-to-bound was shown as 13.9% against about 18% when measured on mature cohorts. |
| D40 | 6 | Every experiment is sized for the SMALLEST effect we would ship (mde_relative == ship_min_relative_lift, enforced at construction). "Achieved power" (post-hoc, computed from the observed effect) is replaced by power at the pre-registered effect. SHIP still uses the point estimate as the brief specifies; the result now reports whether the lower CI bound clears the threshold and warns about winner's-curse risk when it does not. p-values below 0.001 display as "< 0.001". | Audit finding B-19: A was sized for +30% but shipped at +20%. |
| D41 | 2 | N_TRUE_AGENCIES raised from 1,500 to 3,000 (the brief said about 1,500). Sizing A for its 20% ship threshold needs about 860-1,070 agencies per arm at the observed baseline, i.e. about 2,500 mature agencies in total; 3,000 agencies is the smallest round number that clears it with margin. This replaces D10's "tune the funnel to power A at +30%". The funnel is still deliberately generous. | Power analysis, not outcome tuning. |
| D42 | final-1 | Stale-page defence: footer fingerprint (first 10 hex of SHA-256 over sorted marts CSV names and bytes) + as-of date + seed + agency count on BOTH pages; CI `git diff --exit-code` on docs after `make all`; `scripts/verify_live.py` for live checks. The fingerprint is deliberately not the commit SHA (circular). The stale memo reported externally was not reproducible (see AUDIT_LOG), so no repository change could be tied to it as a root cause; the defences make recurrence visible. | Deployment truth. |
| D43 | final-2 | Output rounding rule: every float written to a marts CSV, `outputs/ranked_accounts.csv` or the page JSON is rounded to 10 SIGNIFICANT digits (`bgos/rounding.py`); statistics stay full precision in memory. 10 digits removes build-to-build last-bit noise (about 1e-16 relative) while keeping money to the cent and p-values to 10 digits, which a 6-digit rule would not. Requirements were already exact `==` pins matching the tested environment; the README now records Python 3.12.2. | B-22. |
| D44 | final-3 | Experiment C leads with ABSOLUTE lift (CI) and reports the minimum detectable effect at 80% power for its actual n (brentq on the same power function used elsewhere, cross-checked against statsmodels); relative lift is a secondary line only. The decision logic is untouched (INCONCLUSIVE). Experiment A gets a labelled OBSERVATIONAL panel (ICP vs non-ICP first-submission rate inside its control arm, Wilson CIs, SQL file `experiment_a_icp_split.sql`); on synthetic data it holds by construction because the generator never lets non-ICP agencies submit, and the panel says so. | B-23, B-24. |
