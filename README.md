# Broker Growth OS

This project simulates the growth operating system for Hedge, an AI-native specialty insurance wholesaler. It models the broker funnel from lead identification through repeat submissions, identifies activation bottlenecks, scores agency fit, and provides an experiment framework for acquisition, onboarding, and reactivation.

> **All data is synthetic.** Every agency, touch, submission and result in this repo is generated by `src/bgos/generate.py`. Nothing here states or implies anything about Hedge's real conversion rates, customers, carriers, funding or headcount. Experiment results are **simulated results that demonstrate the method**: the generator plants known effects (+30%, +15%, and a null) so tests can check the pipeline recovers them.

Anything about Hedge that this project assumes is listed under "Assumptions to validate in the first 30 days" in [STRATEGY_MEMO.md](STRATEGY_MEMO.md).

## Quickstart

```bash
make setup       # create .venv and install pinned dependencies
make all         # data, clean, score, metrics, experiments, ai-demo, docs
make dashboard   # open http://localhost:8501
make test        # full regression suite
```

`make all` is deterministic (global seed 42 in [config.py](config.py)): two runs produce byte-identical files. Individual steps: `make data`, `make clean`, `make score`, `make metrics`, `make experiments`, `make ai-demo`, `make docs`. `make reset` deletes generated files. No API key and no network are needed for anything.

## The funnel

Raw Lead, ICP-Qualified Agency, Engaged Broker, First Submission (complete, underwriting-ready), Quoted, Bound, Repeat Submission (another complete submission within 90 days of the first bind). Stages are strictly nested, so counts can only taper. Full definitions: [DATA_DICTIONARY.md](DATA_DICTIONARY.md).

## Design decisions

The full log is [DECISIONS.md](DECISIONS.md). The ones worth knowing:

- **Funnel as code, strictly nested.** Activity from agencies that skip stages is reported as out-of-funnel, never silently dropped.
- **Every metric is a SQL file** and each is cross-checked in tests against an independent pandas computation.
- **No vanity metrics.** Sends and LinkedIn connections never appear as results; source quality is judged by bind and repeat, and tiny-n sources (n < 20) are suppressed.
- **Transparent scoring.** Five weighted components, each in [0, 1], with a reason string naming the top two drivers.
- **Experiments can say no.** Sample size is recomputed from the observed baseline; underpowered wins return ITERATE/INCONCLUSIVE, not SHIP. Arms are assigned with stratified randomization and an SRM check guards assignment.
- **AI is human-in-the-loop.** Deterministic mock by default; optional real provider only if `ANTHROPIC_API_KEY` and `BGOS_LLM_MODEL` are set. Drafts always require review and the codebase contains no send function (a test greps for one).
- **Honest about plumbing checks.** The Tier 1 > Tier 2 > Tier 3 first-submission ordering validates the pipeline only: the generator makes conversion depend on fit, so it is not evidence of predictive power.

## Known limits

- The data is synthetic and the funnel is deliberately generous (about a third of raw leads reach a first submission) so that Experiment A is statistically powered with about 1,500 agencies. Real baselines will be lower and need far larger samples; the sample-size calculator will say so.
- Planted effects are plumbing tests, not findings. B (+15%) and C (null) are intentionally underpowered.
- Every experiment result in this repo is one simulated draw of a design with imperfect power. `make sweep` re-runs 40 seeds and writes [docs/seed_sweep.json](docs/seed_sweep.json): A returns SHIP in most but not all seeds, B never ships, and C occasionally looks significant by chance.
- Running three experiments at once carries a multiple comparisons risk (no alpha adjustment is applied). A real programme would pre-register one primary experiment.
- One seed, one 12-month window, no seasonality, flat commission assumption, no underwriting profitability (loss ratio) or carrier-capacity constraints.
- Deduplication blocks on state, so a duplicate with a missing state is not auto-merged.
- The pipeline projection is assumption-driven and excludes repeat revenue.
- The real-LLM provider is only tested with a fake client; it has never been run against the live API here.
- Hedge-specific assumptions are unverified and listed in [STRATEGY_MEMO.md](STRATEGY_MEMO.md).
